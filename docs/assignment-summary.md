# 컴퓨터 네트워크 과제 핵심 정리

출처: [과제 설명서](<과제 설명서.pdf>) (2026. 11. 5.자, PDF 쪽수 기준). 자체 프로그램 명세는 [요구사항](01-func/01-requirements.md)·[기술 구조](03-tech/01-architecture.md)에서 별도 관리한다.

## 핵심 목표와 범위

**2차 과제는 Wireshark로 명령어 실행 패킷을 수집하고, 명령어 출력과 프로토콜 동작을 연동 분석하는 과제다.** (2~4쪽)

| 구분 | 2차 과제 | 3차 과제 예고(예정) |
| --- | --- | --- |
| 도구 / 언어 | Wireshark (구현 없음) | 조별 개발 패킷 분석 프로그램 (C, Python, Java 등) |
| 명령어 | `nslookup`, `curl`, `netstat` | `nslookup`, `curl`, `netstat`, `ping`, `traceroute` |
| 환경 | 1차 과제 Linux 환경 | 1~2차 Linux 환경 |

## 실습·분석에서 다룰 내용

순서: **환경(Ubuntu IP·네임서버) 확인 → Wireshark 수집 → 명령어 실행 → 패킷 선별 → 출력·패킷 연동 분석** (4·10~11쪽).

| 대상 | 분석 내용 | 결과서 연결 증거 |
| --- | --- | --- |
| `nslookup` (UDP·DNS, 12~17쪽) | 네임서버 질의·응답 흐름, IPv4(A) 질의·응답 2개 선별(IPv6 제외), **UDP/DNS 스트림 인코딩·디코딩 필수 확인**(예시 필터: `udp && ip.addr==210.93.48.196` → `dns`) | 조회 도메인·반환 IP와 DNS 메시지 바이트 대응 |
| `curl` (TCP·HTTP, 18~32쪽) | SYN→SYN+ACK→ACK 연결, HTTP 요청·응답(예시: `curl -v www.tukorea.ac.kr`, `307 Temporary Redirect`), FIN 종료 흐름(예시 필터: `tcp/http && ip.addr==210.93.48.59`, TCP 9개 중 HTTP 2개) | 터미널 출력과 TCP 스트림·단계별 제어 패킷 대응 |
| `netstat -an` (TCP 세션) | `curl` 세션 상태(`TIME_WAIT` 등) 확인 | 로컬·원격 주소·포트와 TCP 연결 종료 흐름 연계 |

## 예시와 미정 사항

- **관찰값 기준:** 설명서의 IP(18쪽 구성도 `210.93.48.196` vs 본문 `210.93.48.59` 불일치 포함)·포트·패킷 수·`307` 응답은 예시이므로 본인 실습 결과로 기록한다.
- **미정·차이:** 조 구성, 3차 마감·세부 양식은 추후 공지된다(질문은 e-class 활용; 5·33쪽). 3차 예고의 `netstat`·`traceroute` 범위는 후속 공지와 대조한다.

## 결과서 권장 구성

1. 지정 양식 표지
2. 실습 환경 (Linux 환경, IP·네임서버, 수집 인터페이스)
3. DNS 분석 (명령어 출력 → 질의·응답 → 스트림 인코딩·디코딩)
4. TCP·HTTP 분석 (명령어 출력 → 연결 설정 → 요청·응답 → 연결 종료)
5. 세션 상태 분석 (`netstat` 출력과 TCP 종료 흐름 대응)
6. 결론 (명령어·프로토콜 연관성 및 예시와의 차이)
